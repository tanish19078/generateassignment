# Project File mode

Project File turns a structured context pack from an existing repository-aware AI session into a convention-locked Word report. Frontend and DBMS reports are supported. Java is intentionally unavailable until its report convention is defined.

## Workflow

1. Select **Project File**, then **Frontend** or **DBMS**.
2. Copy the mode-specific collector prompt from PractiGen.
3. Paste it into the AI session that already has the project repository in context.
4. Paste or import the returned JSON context pack.
5. Validate the pack. Required implementation facts must be supplied; PractiGen does not invent them.
6. Upload PNG/JPEG screenshots using the filenames declared by the context pack. This can wait until export, but every declared image is required in the final document.
7. Build, review, and export the report.

The workflow is hybrid. Supplied report prose is preserved. Only blank `report_sections` fields are completed through the configured Groq/Cerebras model. A complete context pack therefore needs no Project File LLM call.

## Trust boundary

- Collector prompts require read-only repository inspection.
- Secrets, `.env` values, credentials, and private data must never be returned.
- Required facts, SQL, schema details, execution results, screenshots, and references are never generated by the fallback.
- Unexecuted DBMS outputs must remain labelled expected or not independently verified.
- Screenshot URLs and filesystem paths are rejected. Export accepts verified PNG/JPEG bytes only.
- Context and reports are validated again during export.

## Frontend report

Order:

1. Provisional title page
2. Abstract
3. Table of contents
4. Introduction
5. Problem Definition and Requirements
6. Proposed Design / Methodology
7. Results
8. References, when supplied

The collector captures the stack, pages/routes, components, state, API integrations, responsive design, accessibility, testing, file structure, result evidence, and a 10-15 item screenshot plan. Results are placed on separate pages where practical.

## DBMS report

Order:

1. Provisional title page
2. Table of contents
3. Introduction
4. E-R Diagram
5. Database Schema
6. Use Cases with SQL and corresponding output/screenshots

The collector captures the database dialect, entities, attributes, keys, constraints, relationships, cardinalities, normalization, tables, `CREATE TABLE` SQL, and implemented use cases. The library-system wording in the supplied guideline is treated as an example, not a mandatory domain.

## Formatting

- Times New Roman throughout
- Major heading: 16 pt, bold, left-aligned
- Subheading: 14 pt, bold, left-aligned
- Body: 12 pt, justified, 1.5 line spacing
- Frontend caption: 12 pt, centered
- DBMS caption: 10 pt, centered
- Tables and figures are numbered sequentially

The institutional title-page template and reference style are pending. The current cover is deliberately generic and uses only supplied metadata.

## API

| Endpoint | Method | Purpose |
|---|---|---|
| `/api/project/prompt/<submode>` | GET | Return the versioned collector prompt and report format |
| `/api/project/validate` | POST | Parse, normalize, and validate pasted context JSON |
| `/api/project/generate` | POST | Preserve supplied prose and complete only blank sections |
| `/api/project/download` | POST | Revalidate and export a `.docx` report |

Context schema version is currently `1`. Supported `submode` values are `frontend` and `dbms`.

## Image limits

- PNG and JPEG only
- Maximum 16 images
- Maximum 1 MB per optimized image
- Maximum 2.5 MB decoded image data per report
- Maximum 16 million pixels per image on the server

The browser resizes large images before export. Images are intentionally omitted from session restore and must be selected again after refreshing the page.
